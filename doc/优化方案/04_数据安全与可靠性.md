## 2. API 密钥安全存储与不泄漏（P0）

**目标**：密钥永不出现在——磁盘明文、渲染进程可读内存、日志、错误消息、构建产物。

1. **存储加密**：用 OS 密钥库（macOS Keychain / Windows Credential Manager / Linux Secret Service），如 `keyring` crate；退而求其次用主密码派生密钥 + AEAD（如 `chacha20poly1305`）加密后落盘。当前明文 `config.json`（[`ai_client.rs`](../../src-tauri/src/ai_client.rs) 第 57-64 行）须迁移，迁移后删除明文文件。
2. **不回传前端**：`load_api_config` **只返回 `base_url` + `has_key: bool`（或掩码 `sk-****abcd`）**，绝不返回真实 key（改 [`commands.rs`](../../src-tauri/src/commands.rs) 第 98-109 行）。前端 [`aiStore.ts`](../../src/stores/aiStore.ts) 第 40 行的 `apiKey` 明文态移除；[`App.tsx`](../../src/App.tsx) 第 32/42/117-122 行的 key 输入仅在"保存"时单向写后端，不回读回填。
3. **仅后端持有**：调用上游时由 Rust 侧从密钥库读取并注入 `Authorization` 头，前端永不接触 key（现状调用已在 Rust，改造成本低）。
4. **日志/错误脱敏**：任何日志与错误消息过滤 `Bearer ...`、`api_key`、`sk-` 前缀（配合 03 §7 错误契约）。
- 验收目标：全量代码/日志/磁盘中 0 处出现明文 key（假设：使用密钥库或 AEAD，测试用假 key `sk-TEST`）。

## 3. 请求 / 响应隐私（P1）

- **最小化上下文**：仅发送用户当次必要内容，不隐式附带历史/系统信息（现状文本仅单条 user 消息，[`ai_client.rs`](../../src-tauri/src/ai_client.rs) 第 143-145 行，隐私面较小，保持）。
- **本地留存可控**：结果落盘目录（03 §6）应文档化，并提供"清空本地数据"入口（破坏性，见 §6）。
- **传输安全**：强制 `https`，拒绝明文 `http` base_url（除本地 mock）；显式 TLS 后端（03 §8 / H3）。
- **不上传遥测**：当前无遥测，方案不引入任何第三方数据上报。

## 4. 生成内容审核边界（P1/P2）

- 现状：提示词原样发往上游（[`commands.rs`](../../src-tauri/src/commands.rs) 第 6-17 行），无任何本地边界处理。
- 方案：
  1. **依赖上游审核**为主：捕获上游 `CONTENT_POLICY` 类错误，映射为友好拒绝（03 §7），不重试、不绕过。
  2. **不做本地关键词黑名单绕过**：明确产品定位为"合规调用上游能力"，不实现任何规避审核的机制。
  3. 对用户输入长度/大小设上限，避免异常请求。
- 原则：审核拒绝时如实告知，不提供"绕过"路径。

## 5. 持久化原子写与可靠性（P1）

- 现状 `fs::write` 直接覆盖配置（[`ai_client.rs`](../../src-tauri/src/ai_client.rs) 第 63 行）与 PPT（第 319 行），崩溃/断电会留下半截文件。
- 方案：**临时文件 + fsync + rename** 原子替换（同目录 `.tmp` → rename），配置/历史/结果统一走该封装。
- 历史库（03 §6）写入采用事务（SQLite）或追加+校验（JSONL），启动时校验并可从损坏中恢复（保留 `.bak`）。
- 验收目标：写入中途 kill 进程后重启，配置文件不损坏（要么旧值要么新值，无半截 JSON）（假设：故障注入可模拟）。

## 6. 危险操作确认 & Agent 非破坏性（P0 原则）

- **破坏性操作清单**：清空历史、删除单条历史/结果文件、覆盖已有导出文件、清空本地数据、迁移删除旧明文 config。
- **强制二次确认**：所有破坏性操作须经 Tauri `dialog`（已引入，[`lib.rs`](../../src-tauri/src/lib.rs) 第 11 行）确认对话框，默认按钮非"删除"。
- **Agent 边界（核心原则）**：02 §8 规划的生成助手**只产出建议**（提示词改写、参数推荐、失败诊断），严禁自动执行：写文件、删除、发起付费生成、修改配置。任何落地动作由用户显式点击触发。
  - 现状 `src/agent/` 的 SQL mock（[`AgentManager.ts`](../../src/agent/AgentManager.ts)）虽为死代码，但其 `optimize` 返回 `sql.toUpperCase()`（第 81 行）之类"自动改写"范式不得沿用为自动执行。
- 验收目标：自动化流程中 0 次未经确认的写盘/删除（假设：审计所有 invoke 路径）。

## 7. Tauri 权限收敛（P1）

- 现状 [`capabilities/default.json`](../../src-tauri/capabilities/default.json) 开 `fs:default` + `shell:default`（第 10-11 行），超出当前业务所需。
- 方案：
  1. **移除 `shell:default`**（无正当用途；导出/打开文件用 dialog + opener 白名单）。
  2. **`fs` 收敛为 scoped 权限**：仅允许读写 `~/.z-biz-tool-aigen/**` 与用户经 dialog 显式选择的路径，禁止任意路径。
  3. 保留 `clipboard-manager`、`dialog`；`core:default` 按需。
  4. 开启 CSP（改 [`tauri.conf.json`](../../src-tauri/tauri.conf.json) 第 23 行）：`default-src 'self'; img-src 'self' asset: https: data:; connect-src 'self' https:; style-src 'self' 'unsafe-inline'`（按实际资源微调）。
- 验收目标：capabilities 中 shell 权限为 0；fs 均为 scoped；CSP 非 null。

## 8. 成本控制（P1/P2）

- 现状：无任何额度/成本感知，图片可一次 `count` 到 10（[`ImageGenPanel.tsx`](../../src/components/ImageGenPanel.tsx) 第 116 行），文本无 `max_tokens`（[`ai_client.rs`](../../src-tauri/src/ai_client.rs) 第 141-147 行）。
- 方案：
  1. **参数上限**：`count`、`max_tokens`、视频时长/分辨率设硬上限并提示成本影响。
  2. **生成前预估提示**：批量/多模型对比（02 §4/§7）前展示"将发起 N 次请求"确认。
  3. **token/用量统计**：记录上游返回的 `usage`（03 §6 数据模型），历史可查看累计消耗。
  4. **失败不重复扣费**：重试仅针对未产生计费的结果（网络层失败），避免重复付费生成。
- 验收目标：批量任务在执行前给出请求数确认；历史展示每条 usage（假设：上游返回 usage 字段）。
