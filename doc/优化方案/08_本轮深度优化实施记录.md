## 8.4 跨语言命令契约：**Tauri 的参数在两侧各写一遍，却没有任何东西把它们绑在一起**

### 8.4.1 问题

Tauri v2 的命令参数**在 Rust 与前端各写一遍**：Rust 侧是 snake_case 签名
（`save_export(target_path, record_id, ref_index, text, allow_overwrite)`），
前端侧必须传 camelCase（`{ targetPath, recordId, refIndex, text, allowOverwrite }`）。

**TypeScript 不知道 Rust 的签名长什么样** ⇒ 前端把 `allowOverwrite` 拼错，
`tsc` 照样通过；运行时 Rust 收到 `None` ⇒ `allow_overwrite.unwrap_or(false)`
⇒ **「覆盖」永远不生效，界面却提示「已导出」**。
全程无任何报错，**纯静默降级**。

同类风险：`recordId` / `refIndex` / `kind` / `providerId` … 共 16 个命令、24 个调用点。

### 8.4.2 做法：**不写死清单，直接读 Rust 源码自动比对**

`src/_shared/tauriContract.test.ts` 做了两件事：

1. 读 `src-tauri/src/commands.rs`，正则解析出每个 `#[tauri::command]` 的
   **命令名 + 参数名**，把 snake_case 转成 Tauri 的 camelCase，
   并区分「注入参数」（`State<…>` / `AppHandle`，前端不传）与「必填 / 可选」；
2. 扫 `src/**/*.{ts,tsx}`（排除测试文件）里所有 `invoke("cmd", { … })` 调用点，
   解析出**命令名 + 顶层参数键**。

然后断言五条：

- 每个前端 invoke 的命令**真实存在于 Rust 侧**；
- 前端传的**每个**参数名都在 Rust 的可传参数里（抓**拼错**）；
- Rust 的**必填**参数前端都传了（抓**漏传**）；
- Rust 侧的命令**要么被前端调用，要么在「预留未接线」清单里显式声明**；
- 「预留未接线」清单里的命令**必须真的没被调用**（防止清单变成垃圾桶）。

**不写死任何参数清单** ⇒ Rust 那边改了签名，本测试自动跟着变，不会过期。

### 8.4.3 顺带查出的一件事：一个**实现了但前端零调用**的命令

`list_generations` 在 `lib.rs:26` 注册为 command，返回 `state.jobs.snapshot()`，
但**全仓前端零调用**（`grep -rn list_generations src` ⇒ 0 命中）。

它不是 bug —— 当前前端用「事件推送 + `get_generation` 对账」两条路就够了，没有全量列表的界面入口。
但**「实现了、注册了、没人用」这件事本身不该沉默** ⇒ 已进「预留未接线」清单，
并写明理由。清单是**显式声明**，不是沉默。

### 8.4.4 写这个测试时踩到的两个解析器坑（都栽在「量具」上）

| 坑 | 现象 | 真因 |
|---|---|---|
| Rust 生命周期 `'_` 被当成**字符串引号** | 解析出「所有命令的可传参数都是空」 | `State<'_, AppState>` 里的 `'` 开了字符串模式，后面全部内容被吞进「字符串」⇒ 整条命令只解析出 1 个参数（`state`）。**「量具坏了」的现象与「数据坏了」完全一样** |
| 前端**简写属性** `{ id }` 没被识别 | `invoke('delete_template', { id })` 解析出 0 个键 | 简写属性没有冒号，键名就是标识符本身 |

⇒ 第一版解析器报「13 处不一致」，**全是假的**。修好后：**0 处不一致**（当前契约是健康的）。
⇒ 教训：**任何「自动比对」工具，第一次跑出来的结果必须逐条归类核对**，
否则「全是红」会被当成「数据坏了」而去改正确的代码。

## 8.5 导出流程：**覆盖确认**是本仓唯一的数据出本机路径

`src/_shared/export.ts` 的失败形态全是静默的：

- 不弹确认框就覆盖 ⇒ 用户已有文件没了，**无报错**；
- 弹了确认框但用户点了「取消」仍然覆盖 ⇒ 同上；
- 用户点了「覆盖」却没带 `allowOverwrite` ⇒ 后端按「不允许覆盖」处理，
  界面却提示「已导出」⇒ **说了假话**。

`export.test.ts`（13 条）钉住：用户取消对话框 ⇒ 不碰后端；`CONFLICT` + 用户点取消 ⇒
**只调用后端一次**且 `allowOverwrite=false`；`CONFLICT` + 用户点覆盖 ⇒ **调用两次**且第二次带 `true`；
确认后仍失败 ⇒ 不得报成功；错误消息里的密钥形态被洗掉。
